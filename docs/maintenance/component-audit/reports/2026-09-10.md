## 各组件详情

### api-docs-operation-target(OperationTarget)

- **修复(本轮落地)——段级复制按钮的可访问名不含地址值**。host / path 两段是 `<button :aria-label="t.copyHost"><code>{{ baseUrl }}</code></button>`。accname 算法里 `aria-label`(步骤 2C)优先于 name-from-content(2F),所以 `<code>` 中的地址在无障碍树里被整体屏蔽。**复现输入**:`<OperationTarget :hosts="[{ id: 'prod', label: '生产', baseUrl: 'https://api.example.com' }]" path="/v1/deployments" />`,读屏 Tab 到两段——只播报「Copy host, button」「Copy path, button」,用户能知道有个 host 可复制,却听不到它是什么;在仓库两张参考页(`endpoint-reference.vue` / `index.vue` story)上 host 值不在其它位置出现(环境选择器只显示环境名「生产」,identity 头只显示 path)。同时按钮的可见文本(地址)不在可访问名内,直接违反 **WCAG 2.5.3 Label in Name(Level A)**:「For user interface components with labels that include text …, the name contains the text that is presented visually」——语音输入用户念出屏幕上的地址也无法命中该按钮。**修法**:可访问名改为「标签前缀 + 当前值」——`hostName = \`${t.copyHost} ${baseUrl}\``、`pathName = \`${t.copyPath} ${props.path}\``(如 `Copy host https://api.example.com` / `复制环境地址 https://api.example.com`);copied 态仍翻转为完整成功句,tooltip 文案不变(值就在旁边)。`ApiTargetLabels.copyHost / copyPath` JSDoc 改为「可访问名前缀,值会被追加」。**为什么不用 sr-only 前缀 + 文本内容**:sr-only 文字会进入用户的手动选区(`select-text` 是本组件明文可供性),Ctrl+C 会带上「Copy host」;也不用 `aria-describedby` 指向 `<code>`——`UTooltip` 打开时 Reka 会把 trigger 的 `aria-describedby` 指向 tooltip,两者冲突。**行为契约**:props / emits / labels 键零变化;AT 可感知的名字变长,属修正信息丢失而非改变语义——与 `f-0c1cd3397501` 不同,这里不存在需要人工二选一的 i18n 键决策,只有一个显然的修法,故按 §5「收益明确且能同 PR 改完所有仓库内调用点」判 modified,仍在 PR 描述列为人工决策点。**测试**:`operation-target.spec.ts` 的 13 处 `button[aria-label="复制 host / path"]` 精确选择器改为前缀匹配 helper(`hostSegment` / `pathSegment`),`names` 序列与英文默认断言改为含值;新增「names each segment with its value, so a screen reader hears what gets copied」(含切环境后名字随 host 变化),**旧实现下失败**(已实测:12 failed / 5 passed,新用例在列),修复后 17/17。severity medium。**推翻既有裁定(人工决策点)**:08-11 报告曾写「WIG 无 label-in-name 条款,分段按钮『可见文本=被复制值、可访问名=动作句』是 references 明文契约,不立案」。复核:`index.md` 只规定「段文本即复制控件 + 光标 / 下划线 / tooltip 表明行为」,`ApiTargetLabels.copyHost` JSDoc 只说「Accessible name for the host segment」,均未规定名字**不含**值,不构成排除本修法的契约;而 WIG 不含 2.5.3 不等于 2.5.3 不适用——`focus-a11y.md` 以 WCAG 为对比度基线,本仓库 a11y 目标即 WCAG。本轮以 WCAG 2.5.3(Level A)+ 读屏信息丢失两条依据推翻 08-11 的「不立案」,并在 PR 描述列为人工决策点。**依据**:WCAG 2.5.3 Label in Name;HTML-AAM / accname「aria-label 优先于内容」;`focus-a11y.md`「纯图标按钮必须有可访问名称」的精神是「名称要能识别对象」;Web Interface Guidelines「Icon-only buttons need aria-label」只约束存在性,本修复补齐「名称要说清复制什么」;仓库内 `FieldItem` 锚点按钮已是「Copy link to amount」(含对象)的同类先例。

### foundation-copy-button(CopyButton + useCopy)

- **晋升 / 精简 / 重构**:无。98 行 `UButton` + 可选 `UTooltip` + sr-only region,双分支模板重复是 `inheritAttrs: false` 多根组件的明文取舍(08-27 裁定,`copy-button.spec.ts` 锁定 attrs 契约);`useCopy` 仍是全仓剪贴板逻辑唯一归宿(`writeText` / `execCommand` 全仓仅 `useCopy.ts`),`useFieldAnchor` 属「复制深链接并滚动定位」的明文豁免。registry 依赖(`geist-foundation` + `foundation-use-copy`)与 import 一致。
- **新 finding(low,open,deferred)——组件自有 live region 与 toast 自播报重复**。`useCopy` 成功路径无条件 `useToast().add({ title })`;核证 `@nuxt/ui` 4.9.0 `Toast.vue`:经 `useForwardProps(reactivePick(props, …, 'type'))` 透传 reka `ToastRoot` 的 `type` 且**不设默认**;`reka-ui` 2.9.10 `ToastRoot` 的 `type` 默认 `'foreground'`,`ToastRootImpl` 对每个 toast 渲染 `ToastAnnounce`(`VisuallyHidden`、`role="alert"`、`aria-live="assertive"`),两帧后以 `ToastProvider` label(默认 `Notification`)前缀播报标题。**复现输入**:`<UApp><CopyButton value="x" /></UApp>` 点击一次——DOM 先出现 CopyButton 自有 `role=status`(polite)文本 `Copied to clipboard`,随后出现 reka 的 `role=alert` 文本 `Notification Copied to clipboard`;同一次复制被两个 region 播报,且 assertive 会打断 polite。OperationTarget 的段级 `segmentStatus` region 同理——其注释「ONE polite region … two regions would compete」在 toast 存在时并不成立。**修法(人工决策)**:① 移除 CopyButton 与 OperationTarget 的自有 region,播报统一交给 toast,同步收窄 `buttons.md` / `code-sample.md` / `index.md` 的「polite live region 播报」表述与 `operation-target.spec` 的 2-region 断言;② 保留组件 region、让 toaster 不播报——reka 无此开关,不可行。推荐 ①。**为什么不本轮修**:跨 foundation + kit + 三份 reference 的播报归属决策,`buttons.md` / `index.md` 各在多个 item scope 内,按 §7「修复量大且跨契约边界」记 deferred。**依据**:Web Interface Guidelines「Async updates (toasts, validation) need `aria-live="polite"`」——toast 已满足,组件再加一层属重复;`code-sample.md`「copy result announcement is owned by CopyButton」与实况(toast 也播报)不符,记为被违反的 claim。**证据边界**:基于依赖源码阅读与 DOM 级推演,未做真实读屏实测;evidence 绑定 `@nuxt/ui` 与 `reka-ui` 两个 dependency(reason 写明重评条件)。
- **复核无回归的既有契约**(逐条对照 `buttons.md` CopyButton 节):`value` 必填、`label` / `copiedLabel` 双态可访问名、`copiedLabel` 未传 `successMessage` 时复用为成功 toast(`chrome-labels.spec` 锁定)、完整句约定(ADR「复制 toast 只接受完整 successMessage / failureMessage」)、`tooltip` 默认关、idle → copied 约 2s 脉冲(图标 + 颜色双通道,无布局位移)、失败只出 error toast 不进 copied 态、`onScopeDispose` 清 timer;`copy-button.spec` 2 用例 + `chrome-labels.spec` useCopy 6 用例全绿。gallery `Buttons.vue` 三个示例(默认 / tooltip / 本地化 outline)与契约一致。
- **反向横扫**:`copied ? copiedX : x` 三元翻转仅 CopyButton 内部 8 处(双分支各 4);`aria-live` 全仓 8 处(AnnotationPopover / CopyButton ×2 / OperationTarget ×2 / EnumTable / SidebarNav / SiteSearch),08-22 已判「契约统一、实现各异」,本轮新增的是「与 toast 重复」这一维度,只影响会触发 toast 的 CopyButton 与 OperationTarget;`...props.labels` 合并一行式 12 处属既定约定。
- **为什么没改看起来可改的**:
  - `UTooltip` 分支下 Reka 会在 tooltip 打开时给按钮加 `aria-describedby`,读屏会把与 `aria-label` 相同的文案再读一遍——这是 Nuxt UI tooltip 的固有行为,`tooltip` 默认关且密集工具条明文不用,不记 finding。
  - 2s 内连点两次,region 文本不变故读屏不会二次播报——toast 会(每次新 toast 都 announce),且若人工采纳修法 ① 该问题随之消失,不单独处理。
  - `inheritAttrs: false` 连 `id` / `data-*` 一并丢弃——`buttons.md` 明文「需要布局类时在外面包一层」,是设计。
