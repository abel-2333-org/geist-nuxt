## 修复边界

### OperationTarget

保留 `Copy host <value>` / `Copy path <value>` 的 idle 名称，copied 态使用「完整成功句 + 当前可见值」。tooltip / toast 仍传原完整本地化成功句，避免把长地址重复加入反馈。

### 单来源复制播报

Nuxt UI 4.9.0 将 toast `type` 透传给 Reka UI 2.9.10；后者将 background 映射为 polite。组件自有 status 与默认 foreground/assertive toast 原先构成两个来源，不能宣称默认 toast 已满足 polite。

真实 UApp / useToast / Reka 集成测试仅 mock clipboard，等待 toast 的 alert 节点挂载后检查同一消息恰有一个 polite live region；覆盖 plain CopyButton、tooltip CopyButton、OperationTarget host 与 path。CopyButton 的 `inheritAttrs: false` 和外层布局 wrapper 契约保留。ResponseExample 的 panel 状态 region 与复制无关，未删除。

### 换行标签迁移

新增 `labels.wrap`（默认 `Line wrap`），状态只由 `aria-pressed` 表达。测试从任意已持久化状态切换两次，验证英文与中文名称稳定、pressed 两态正确；共享状态与 cookie 不变。

公开迁移要求：消费项目升级这版 CodeBlock 时，须在同次 registry update 中把旧 `wrapOn` / `wrapOff` 字典项替换成 `wrap`（如 `wrap: '自动换行'`），并运行 typecheck。没有从动作句推断名词的兼容层。只读核对的 onerway-api-next 使用自有 ApiCodeBlock，未发现安装本 kit 或旧键调用；未修改外部项目，未知外部消费者仍需按迁移说明同步。
