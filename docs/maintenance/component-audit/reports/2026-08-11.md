## foundation-copy-button — modified

**问题**(component-reflow §5 + gallery 约定):CopyButton 是已晋升的 foundation 组件,`CodeBlock` / `OperationTarget` 都建于其上,但 `references/components/` 全目录无其条目、`index.md` 决策表查不到「复制到剪贴板」能力、gallery Buttons 组亦无 entry——同类 foundation 原子(SemanticBadge、InlineCode、AnnotationPopover 等)均有两者。下游按选型文档找不到该能力,存在重复自建风险。组件代码本身达标,未改。

**改动**:

1. `references/components/buttons.md` 新增 `## CopyButton` 权威条目(何时用/Anatomy/props/State/A11y/勿臆造),显式记录:完整句 toast 契约(ADR)、多根组件 class 静默丢弃陷阱(源自 OperationTarget 已付学费的注释)、副作用边界(复制+导航保持调用方自建);
2. `references/components/index.md` 动作决策表补「复制一个值到剪贴板」行;
3. `app/components/gallery/Buttons.vue` 新增 GalleryEntry,三个真实示例(默认 ghost、tooltip、中文本地化 outline),Usage 指回 `buttons.md#copybutton`。

**为什么没改模板双分支**:tooltip / 非 tooltip 分支重复了 UButton + live region 各一次,看似可用 `UTooltip` 的 `disabled` prop 合并。不改:合并后无 tooltip 模式也会被 Reka Tooltip trigger 包裹,DOM 形态与 fallthrough 行为改变——本组件的多根结构是 OperationTarget 明文依赖的行为契约(API shape 未变 ≠ 非破坏),收益(省 10 行)不抵行为契约风险。

## foundation-split-pane-handle — modified

**问题**:`tests/component/` 22 个 spec 中没有 SplitPaneHandle,其核心价值全是 CSS 与类型守不住的行为契约:键盘映射、`preventDefault` 只吞已处理键、disabled 惰性化、主键过滤。SplitPane / CodeRail 两个分发消费方都依赖这些语义,零覆盖意味着回归只能靠人眼。组件代码本身达标(ARIA window-splitter 语义、focus-visible 常驻、状态不只靠颜色),未改。

**改动**:新增 `tests/component/split-pane-handle.spec.ts`(14 例):separator 语义面(role/orientation/value/tabindex/cursor)、方向键 ±1 与 Home/End/Enter 映射、**Tab 不被吞**(键盘陷阱防线)、pointerdown 仅主键、双击复位、active 时 grip 常亮、disabled 全惰性(无 role/tabindex/aria/光标/track/grip/事件)。

**为什么没改 RTL**:ArrowLeft=-1 假定 LTR;WIG 与仓库 references 均未提出 RTL 要求,方向语义翻转牵动 useSplitPane 与两个消费方,属跨契约改动,当前无需求不立案。
