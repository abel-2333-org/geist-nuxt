## foundation-copy-button — modified

**问题**(component-reflow §5 + gallery 约定):CopyButton 是已晋升的 foundation 组件,`CodeBlock` / `OperationTarget` 都建于其上,但 `references/components/` 全目录无其条目、`index.md` 决策表查不到「复制到剪贴板」能力、gallery Buttons 组亦无 entry——同类 foundation 原子(SemanticBadge、InlineCode、AnnotationPopover 等)均有两者。下游按选型文档找不到该能力,存在重复自建风险。复审进一步发现多根/单根模板分支的 attrs fallthrough 不一致,公开说明却写成一律静默丢弃。

**改动**:

1. `references/components/buttons.md` 新增 `## CopyButton` 权威条目(何时用/Anatomy/props/State/A11y/勿臆造),显式记录:完整句 toast 契约(ADR)、布局 attrs 一律由外层 wrapper 持有、副作用边界(复制+导航保持调用方自建);
2. `references/components/index.md` 动作决策表补「复制一个值到剪贴板」行;
3. `app/components/gallery/Buttons.vue` 新增 GalleryEntry,三个真实示例(默认 ghost、tooltip、中文本地化 outline),Usage 指回 `buttons.md#copybutton`。
4. `CopyButton.vue` 显式 `inheritAttrs: false`,使 tooltip / 非 tooltip 分支都不接管外部布局 attrs；`copy-button.spec.ts` 双分支锁定该契约。`CodeBlock`、`OperationTarget` 及 focused specs 一并纳入 CopyButton evidence；共享依赖 `api-docs-code-block` 同批 co-review。

**为什么没合并模板双分支**:tooltip / 非 tooltip 分支重复了 UButton + live region 各一次,看似可用 `UTooltip` 的 `disabled` prop 合并。不改:合并后无 tooltip 模式也会被 Reka Tooltip trigger 包裹并改变 DOM 形态；attrs 路由已由 `inheritAttrs: false` 独立固化,无需用结构重写换取十行缩减。

## foundation-split-pane-handle — modified

**问题**:审计前 `tests/component/` 21 个 spec 中没有 SplitPaneHandle,其核心价值全是 CSS 与类型守不住的行为契约。初次补测后复审发现三条实现缺口:vertical / horizontal 会吞掉正交方向键；拖拽未绑定发起 `pointerId`,第二触点可改值或提前结束；公开 handle 可在 focusable 状态缺少必需 `aria-valuenow`。

**改动**:`SplitPaneHandle` 只处理 orientation 主轴箭头,正交箭头与 Tab 均透传；公开 API 改为必填 `valueNow`,由组件统一输出 `aria-valuenow`。`useSplitPane` 绑定首次 `pointerId`,忽略异源 move/up/cancel 与拖动中的重复 start。`split-pane-handle.spec.ts` 扩为 16 例,新增 `use-split-pane.spec.ts` 1 例覆盖多指针生命周期；SplitPane、CodeRail 两个直接消费者与 composable 同批纳入 evidence。

**为什么没改 RTL**:ArrowLeft=-1 假定 LTR;WIG 与仓库 references 均未提出 RTL 要求,方向语义翻转牵动 useSplitPane 与两个消费方,属跨契约改动,当前无需求不立案。
