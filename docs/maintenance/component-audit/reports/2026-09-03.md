## 各组件详情

### foundation-term-annotation(TermAnnotation)

- **晋升**:无。已是 foundation 根级形态组件,registry 粒度(单文件 + 三个依赖 item)与 Annotation 家族矩阵(壳 + Term/Doc/Field 三形态)一致。
- **精简**:90 行单一职责(glossary 解析 + 壳装配)。`labels` 合并 computed 与 Doc/Field 形态同构,属家族惯例(已有 wont-fix finding `f-fd7282669072` 裁决),不重复记录。
- **优化 / 修复**:**glossary 原型链查找**。`useGlossary()` 返回 plain object(`inject(KEY, {})` 或消费方的对象字面量),`glossary[props.id]` 对 `id="constructor"`、`"toString"` 等 Object.prototype 成员名会命中继承函数而非 `undefined`。复现输入:`<TermAnnotation id="constructor">constructor</TermAnnotation>`(glossary 未登记该 id)→ 实测渲染出 `<button aria-haspopup="dialog">` live trigger、不触发 `console.warn`;打开后 `resolved.term` 为 `undefined`、`InlineMarkdown` 收到 `text=undefined`。这直接违反 `references/components/overlays.md` 的公开 claim「未命中时**优雅降级为纯文本**(stale markdown 永不破页)」与源码注释「Unknown ids degrade gracefully to plain text」。`constructor` 在 SDK 术语表里是现实存在的术语 id,不是理论边角。severity **low**(需特定 id 撞名),影响范围仅 `id` 路径(`entry` 直传不受影响)。最终修法:先用 `Reflect.has(glossary, props.id)` 建立 Vue reactive key 依赖，再用 `Object.hasOwn` 拒绝原型链成员；既保留 late-add 响应性，也维持自有属性语义。依据:overlays.md 降级 claim;审计协议「Universal claims 触发器」——`永不破页` 属 universal claim,存在反例时必须修实现或收窄 claim,本轮选择修实现,claim 保持不变。
- **复审修复**:初版仅用 `Object.hasOwn`，不会为 Vue reactive Proxy 建立缺失 key 的存在性依赖，导致 glossary 初次缺失的 id 后续新增时 computed 不会重算。最终实现补 `Reflect.has` 与 late-add DOM 回归测试。
- **重构**:无。props(`id`/`entry`/`labels`)、默认 slot、`#actions` 关闭后导航的契约与 overlays.md 一致;上轮 finding `f-084ace82f441`(overlays.md 漏记 `entry`)已 resolved,本轮确认文档在位。
- **新增测试**(`tests/component/term-annotation.spec.ts`):① 提供 glossary 但 `id="constructor"` → 纯文本、无 `button`、告警；② reactive glossary 初次缺失 `late`，挂载后新增条目 → trigger 出现。放在 term-annotation.spec 而非共享的 annotation-forms.spec,避免把 Doc/Field 两个 verified item 拉成 co-review owner(与 08-17 的处理一致)。
- **scope 变更**:evidence scope 新增 `foundation/composables/useGlossary.ts`——本次修复的正确性依赖它返回 plain object(`inject(KEY, {})` 或消费方对象字面量);若容器形状改变(如 `Map`),证据应随之失效并触发复审。
- **为何没改 `useGlossary` 改用 `Map` 或 `Object.create(null)`**:`GlossaryMap = Record<string, GlossaryEntry>` 是公开类型,消费方以对象字面量 `provideGlossary({...})` 注入,改容器类型是破坏性 API 变更;组件侧一行守卫即可完整消除缺陷,无需扩大边界。

- **晋升 / 精简 / 重构**:无。自 08-26 verified 以来 owning file、spec、三个消费方(SplitPane / CodeRail / SidebarNav)零变更(仅审计 squash 提交触碰)。
- **优化**:逐条重核 window-splitter 契约——`role="separator"` + `aria-orientation` + `aria-valuenow/min/max` + `tabindex=0`;键盘映射只吞已处理键(Tab 穿透有测试);`disabled` 退化为无语义 spacer;grip 形态 `focus-visible` 环恒在、edge 形态 1px→2px primary 规则做唯一焦点指示;命名 group `group/handle` 防外层 hover 泄漏。全部与 `split-pane-handle.spec.ts`(handle 部分 18 tests)及 `references/kits/api-docs/index.md` SplitPaneHandle 段一致。
- **Universal claims 核证**:源码头注「focus-visible ring … (never removed) in the default grip appearance」——根元素 `outline-none` 仅去默认 outline,grip 形态显式补 `focus-visible:outline-2 … outline-primary`,成立;「State is never color-only」——rest→hover 由 grip 药丸出现(形状)承载、拖动由全局 resize 光标 + 面板实际位移承载,成立。

### foundation-split-pane(SplitPane)

- **晋升 / 精简**:无。260 行全部服务「空间分割 + 拖动」单一职责;内容优先重分配留在 kit `<CodeRail>`(ADR-010 边界)复核仍成立。
- **优化 / 修复**:**复位目标是挂载时快照**。`useSplitPane` 的 `default` 明文接受 `MaybeRefOrGetter`——注释原话「reactive allowed, so a prop-driven default stays live」——而唯一 prop 驱动的消费方 SplitPane 却传入 `props.defaultSize ?? …` 的求值结果。复现输入(DOM 黑盒):`defaultSize=320` 挂载 → `ArrowLeft` 得 344 → `setProps({ defaultSize: 400 })` → `Enter` 复位 → 实测仍为 **320**(期望 400)。severity **low**(MDC/静态页面不会运行时改 `defaultSize`),影响范围仅 Enter / 双击复位路径。修法:传 getter `() => props.defaultSize ?? (isRatio.value ? 0.5 : 320)`;`useState` 首次初始化仍经 `toValue` 取同一值,持久化与钳制路径不变。依据:`useSplitPane.ts` 自身的公开注释契约 + vue-best-practices「props 变化应可预测地传播,不在 setup 里冻结 prop 快照」。
- **重构**:无。断点门控(SSR 恒 stacked → 挂载后翻转)、`useRafTask` 合帧测量、MDC 友好纯字面量 prop、sticky 视口高把手、未测量时 `aria-valuemax` 回退当前值 + `End` 惰性——全部与 spec 及 references 一致,上轮两处修复在位。
- **新增测试**(`tests/component/split-pane-handle.spec.ts` 的「SplitPane separator relationship」组):320 → 344 → 改 default 400 → Enter 得 400。
- **为何没改其它看起来可改的**:`storageKey` / `mode` 同样是挂载时读取——它们是持久化 key 与值域语义,运行时切换意味着换存储槽,reference 从未承诺可变,不动;`stackedStart` 防御性 class、`enabledFrom` 与 CodeRail 的类型不对称、步长常量——08-26 已逐条裁定不动,理由未变。
