### api-docs-schema-composition(SchemaComposition)

第三次作为计划项审计(08-12 首审 clean、08-28 复审 clean、09-09 作为 PR #118 的 co-review owner)。`git diff 139ea71..HEAD` 确认组件、显示模型、测试、reference 与 gallery 自上次 evidence 以来零变更;本次按五份规则源重新过四个维度。

- **晋升**:API Docs 领域专用件(依赖 FieldItem、消费 `CompositionNode` 显示模型),不满足下沉 foundation 的跨领域条件;kit 归属正确,registry 拓扑(`registryDependencies: [api-docs-field-item]`)与源码实际引用一致。
- **精简**:三分支模板重复的 body(description + FieldItem 循环 + 嵌套递归)08-28 已裁定不抽 internal 子组件(wrapper 语义不同、抽取需改 item 拓扑),本次复核结论不变。labels 合并 idiom 属登记表候选 3(不建议抽取),不重复评估。
- **优化(本轮落地)——anyOf 分区按钮缺 `touch-manipulation`**。
  - **风险场景**:任意 `kind: 'anyOf'` 节点(gallery「anyOf — 联系渠道」),触屏设备上快速双击分区标题按钮(开→关)。原按钮未显式限制 double-tap zoom;按 [Pointer Events 的 touch-action 定义](https://www.w3.org/TR/pointerevents3/#details-of-touch-action-values),`manipulation` 禁止这类缩放,同时允许平移与连续缩放。实际是否触发双击缩放取决于浏览器与页面条件,本轮未在触屏真机复现旧行为。
  - **依据**:web-design-guidelines「Touch & Interaction:`touch-action: manipulation`(prevents double-tap zoom delay)」;同 kit 同形 disclosure 按钮(FieldItem 子字段 toggle L548、FieldValueStructure toggle L206)均带该 class,且 `field-item-structure.spec.ts` 以 `classes()` 断言锁定;`references/kits/api-docs/schema-composition.md`「anyOf … 独立开合」的交互面与 FieldItem children disclosure 是同一 anatomy(chevron `rotate-90` + label + `(N)` 计数)。
  - **severity**:low(仅触屏、仅快速连击场景;桌面与键盘无影响)。
  - **修法**:按钮 class 增加 `touch-manipulation`;`schema-composition.spec.ts` 的 anyOf ARIA 用例补一行 `classes()` 断言(与 FieldItem 测试同款写法)。props / emits / slots / 行为契约均未变,非破坏性。
  - **未改 reference**:`schema-composition.md`「Accessibility」节本就不逐 class 记录触控细节,FieldItem 的同类契约也只在测试与源码注释里;为一个 utility 增加 prose 条款只会扩大 co-review 面。
- **优化(复核无回归)**:oneOf 用 `UTabs` + `unmount-on-hide=false`(`@nuxt/ui` 4.9.0 `Tabs.vue` 仍转发 `unmountOnHide` 给 Reka,deep link 契约成立);anyOf 真 `<button>` 持有 `aria-expanded` / `aria-controls`,heading 只做 outline;`hover:bg-muted/40` + `focus-visible:outline-2 -outline-offset-2`(全宽按钮在 `overflow-hidden rounded-lg` 框内用内缩 offset,与 FieldItem 的独立按钮 `outline-offset-2` 分工合理);全部语义 token,无硬编码;`contentId` 用 `useId()` + `encodeURIComponent(variantId)`,`email/primary` 类 id 有测试;empty state 有框。
- **依赖证据(复审补齐)**:`@nuxt/ui@4.9.0` 的 Tabs / Collapsible 转发 `unmountOnHide`,`reka-ui@2.9.10` 的 TabsContent / CollapsibleContent 保留隐藏内容 DOM;这两层共同支撑隐藏字段可寻址与 deep link 揭示。已用原功能提交 `9ecee9f` 和原 base 重新运行 recorder 绑定两项依赖;后续任一 resolution 变化都应触发该 owner 复审。
- **重构**:`<script setup>` + TS;`CompositionNode` 判别联合在类型层排除 `allOf + discriminator`,运行时 `buildFields` 另有 guard 并有测试;`HeadingLevel` 型封顶 6 有测试;命名符合 `component-reflow.md`(领域词 oneOf/anyOf/allOf/discriminator 取自 OpenAPI 规范)。
- **Universal claims 核证**:源码注释「never parses an OpenAPI document and never depends on a consumer's contract types」——文件只 import `TabsItem` 类型与 kit util,成立;「never parsed, prefixed, suffixed or slugified」——`path` 只经 FieldItem 原样进 DOM id,本组件的 `contentId` 用的是 variant id 而非 path,成立;reference「anyOf 绝不渲染成互斥 selector」「allOf 绝不 tabs」——模板三分支结构性成立。
- **为什么没改看起来可改的**:
  - `hint` computed 用模板字面量索引 `t.value[`${kind}Hint`]`——类型经 `as const` 收窄,可读性足够,不改。
  - `watch` 源含 `variantPaths`(派生自 `props.variants`)与 `variantIds`(同源)——两者语义不同(ids 决定 tab 回退,paths 决定 reveal),合并不减 watch 次数,不改。
  - oneOf 面板 `class="border-s border-default ps-4"` 与 anyOf 内容 `ps-9` 的缩进不一致——anyOf 的 36px 是对齐 chevron(`px-3` + `size-4` + `gap-x-2`)的刻意值,oneOf 无 chevron,不是漂移。
  - 初次交付仅检查 class;这只能证明 utility 类名存在,不能代替浏览器计算样式或原生事件验证。复审已补浏览器验证,结果与边界见下方 Gate。
