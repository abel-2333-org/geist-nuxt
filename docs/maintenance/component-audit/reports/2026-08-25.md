## 各组件结论

### api-docs-site-search — modified(status: verified)

**修复(本轮落地)**:① 默认 `placeholder: 'Search guides and endpoints'` 补结尾省略号——符合 Web Interface Guidelines Typography「Placeholders end with …」、Nuxt UI CommandPalette 默认文案 `Type a command or search…` 与姊妹组件 SidebarNav 的既有惯例。② 复审发现 CommandPalette 搜索 input 只有 placeholder、没有独立 label/aria-label,违反同一份 guidelines 的「Form controls need label or aria-label」;现经公开 `input` object 将可本地化的 `modalTitle` 作为 `aria-label` 透传给原生 input,同时显式 `autocomplete="off"`。placeholder 与 accessible name 独立,消费方覆盖 `modalTitle` 时两处结构文案仍保持同一来源。

**行为契约复核(未变)**:同步过滤 + `ignoreFilter` 交付已确定结果的架构与 reference「SiteSearch 契约」逐条一致;异步 search 的 debounce、stale cleanup、三态(searching / error / empty)持久 live-region 播报与 input 独立命名由 `site-search.spec.ts`(11 tests)黑盒锁定;hash 焦点交接(`router.resolve` 单次解码、opaque id、reduced-motion)与测试断言一致;`fuse.js` 全局 `resultLimit` 与 `matches` 高亮契约复核成立。

**为什么没改看起来可改的**:

- **Fuse 索引逐键重建**(`paletteGroups` 内 `new Fuse(items, …)`):文档站量级语料(数百条)构建为亚毫秒级;且 `search` prop 存在时每次键入都会重置 `asyncItems`(新数组引用)→ `sourceGroups` 逐键重算,单纯 memoize Fuse 实例会被引用漂移抵消,完整修复需连带改 `asyncItems` 的写入判等,复杂度不匹配收益,不记 finding。
- **tabindex 焦点交接微模式与 DocsShell 重复**(反向横扫命中):`SiteSearch.onCloseAutoFocus`(同页 hash 交接)与 gallery-private `DocsShell.focusPendingTarget`(跨页 drawer 焦点接力,useState 跨实例存活)只共享「补 `tabindex="-1"` 再 focus」三行,用途、生命周期与滚动策略均不同;抽 util 属投机抽象,且 demo recipe 不进 foundation/kit,不记 finding。
