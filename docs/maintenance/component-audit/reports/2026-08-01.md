## api-docs-lifecycle-badge(clean,首扫)

`LifecycleBadge.vue`(35 loc)+ `lifecycle-preset.ts`(60 loc)。四维度结论:

- **晋升**:域词汇(API lifecycle)→ tone 的映射正确留在 kit preset 层,foundation `SemanticBadge` 保持 vocabulary-agnostic,与 `references/kits/api-docs/index.md`「preset 型徽章」条款一致;无需上移或下沉。

- **优化**:preset 为全部 6 个状态配齐 icon + label,「meaning never rides on color alone」在该链路结构性成立;tone 校准有明文分工(deprecated 走 neutral 为 sunset 保留 error、避免与字段行红色 Required 冲突);gallery(`app/pages/kits/api-docs/index.vue`)全六态陈列;语义 token 无硬编码;分发物无 U+FFFD。
- **重构**:`<script setup>` + TS 达标;`Record<LifecycleStatus, LifecyclePresetEntry>` 使新增词汇漏配即编译报错;`label` prop 覆盖 preset 默认文案的 i18n 通道与 reference 表格记载一致。

**Universal claims 核证**(源码注释触发):

- lifecycle-preset.ts「a lifecycle value is singular per entity, so states never co-occur」——消费方 `FieldItem`(`lifecycle?.status` 单值)与 `OperationHeader`(`lifecycle?: EndpointLifecycle` 单值)的类型契约均只允许单值,结构性成立。
- `LifecycleNotice`「badge and notice can never drift apart」——两形态共享同一 `lifecyclePreset` 常量(tone/icon/label 单一真源),成立。

**为什么没改看起来可改的**:

- `size: 'sm'` 默认值与 `SemanticBadge` 的默认重复——这是 `HttpMethodBadge` 注释明文记录的对齐约定(两徽章在 operation header 同现时尺寸一致),非无意重复,不动。
