## api-docs-lifecycle-badge(modified,verified)

复审按公开 claim、直接 consumers、类型真源和测试重新扩展 scope。四维度结论:

- **晋升**:域词汇(API lifecycle)→ tone 的映射正确留在 kit preset 层,foundation `SemanticBadge` 保持 vocabulary-agnostic,与 `references/kits/api-docs/index.md`「preset 型徽章」条款一致;无需上移或下沉。
- **精简**:两文件粒度即 registry item 的最小依赖闭包;`registryDependencies: [foundation-semantic-badge]` 经其闭包携带 `foundation-badge-utils`,`BadgeTone` 裸引用在源仓库与 copy-in 后两侧同构成立。
- **优化**:preset 为全部 6 个状态配齐 icon + label;tone 校准有明文分工(deprecated 走 neutral 为 sunset 保留 error、避免与字段行红色 Required 冲突);gallery(`app/pages/kits/api-docs/index.vue`)全六态陈列;语义 token 无硬编码;分发物无 U+FFFD。
- **重构**:`<script setup>` + TS 达标;`Record<LifecycleStatus, LifecyclePresetEntry>` 使新增词汇漏配即编译报错;`label` / `title` 接受显式本地化，但空串或纯空白会回退 preset，保留 icon + 非空默认文本的非颜色语义。

**Universal claims 核证**(源码注释触发):

- lifecycle-preset.ts「a lifecycle value is singular per entity, so states never co-occur」——消费方 `FieldItem`(`lifecycle?.status` 单值)与 `OperationHeader`(`lifecycle?: EndpointLifecycle` 单值)的类型契约均只允许单值,结构性成立。
- `LifecycleNotice` 原「badge and notice can never drift apart」过强——两形态仅在默认 tone/icon/label 上共享 `lifecyclePreset`;显式本地化与 form variant 可独立。源码注释已收窄为可验证的默认同源约束。

**为什么没改看起来可改的**:

- `size: 'sm'` 默认值与 `SemanticBadge` 的默认重复——这是 `HttpMethodBadge` 注释明文记录的对齐约定(两徽章在 operation header 同现时尺寸一致),非无意重复,不动。
- 六态 preset 使用独立 literal contract table 锁定 label/color/variant/icon；另覆盖 `LifecycleBadge.label` 与 `LifecycleNotice.title` 的空白回退，避免测试与生产 preset 同源而同步漂移。
- reference 表格未列 `size` prop——kit index 表格是压缩的职责摘要而非穷尽 props 契约(HttpMethodBadge 同样省略),与 overlays.md 显式「**props**:」清单是不同文档体裁,不构成 drift。
