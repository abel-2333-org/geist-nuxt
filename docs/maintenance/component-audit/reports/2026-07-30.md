### 结论 1：f-4a60b6008a52 与 f-7b91ff128432 描述的是**已被替换掉的实现**

两条 finding 都明确指向「有序规则表」，并建议「换成 CommonMark delimiter-run 算法
（左右 flanking + rule of three）」。核实实时代码：

- `git log -- foundation/components/inline-markdown/parse.ts` 只有一个提交 `b497e08`，

  `const rules: Rule[] = [...]` 有序规则表（自称 "zero-dependency tokenizer"）；
- `b497e08` 之后 `parse.ts` 改为 `Lexer.lexInline`（`marked` 17.0.6），delimiter-run
  语义交给成熟 lexer，adapter 只做白名单 + intraword `*` 否决。

也就是说 delimiter-run 改造**已经在同一个 PR 里完成了**，但 finding 没有随之更新

## foundation-doc-annotation — 首次审计，修固定宽面板的长 token 溢出

`foundation/components/DocAnnotation.vue`（134 行）。Annotation 家族的站内文档预览形态。

### 改动：标题槽缺 `wrap-anywhere`，长 token 溢出浮层并被视口裁掉

`AnnotationPopover` 的面板是固定宽度（`w-72 max-w-[calc(100vw-2rem)] sm:w-80`），
`references/components/overlays.md` 把它写成公开契约：

> 长内容浮层宽度受限（`w-72 sm:w-80`，且**不超视口**），完整内容须经 `#actions` 跳转可达（永不死路）

但 DocAnnotation 的标题是裸 `<p class="font-medium text-highlighted">`。作者内容
（front-matter title / description）带不可断 token 时——API 文档里很常见，例如摘要里
直接写一条长 URL，而 `InlineMarkdown` 刻意不支持 autolink、会把它当字面文本——该 token
无法折行。**375px 视口 dark 主题实测**（真实浏览器，非 jsdom；jsdom 无布局，测不出溢出）：

| 状态 | `panel.clientWidth` | `panel.scrollWidth` |
|---|---|---|
| 正常散文标题 | 288 | 288 |
| 标题为 `https://api.example.com/v1/accounts/settlement_reconciliation_batches?cursor=eyJhbGciOiJIUzI1NiJ9` | 288 | **502** |
| 补 `wrap-anywhere` 后 | 288 | 288 |

面板本身没有 `overflow-hidden`，所以文字直接**溢出面板右边界**、压在背后的 Usage
链接上并被视口切断。这是 `overlays.md` 上述 claim 的确凿反例。

修法是两处加 `wrap-anywhere`（标题 + 摘要）。摘要虽有 `line-clamp-4`（隐含
`overflow: hidden`，实测 288 不溢出），但没有 `wrap-anywhere` 时长 token 会被硬裁在
半个字形上；补上后先折行再按 4 行截断，可读性严格更好。这两个类名是仓库既有 idiom
（`EnumTable.vue:263` 对描述文本、`FieldItem.vue` 多处都是 `wrap-anywhere min-w-0`）。
`annotation-forms.spec.ts` 同时锁定标题与摘要的 `wrap-anywhere` 类契约。

### 已核实、未改的部分

- **“The error state never dead-ends” / “error 态不死路”**：`AnnotationPopover` 的 error
  分支同时渲染 Retry 与 `<slot name="actions">`，DocAnnotation 的「Open page」按钮不带
  状态条件。375px **light 主题**实测：error 态面板同时给出 “Retry preview” 与
  “Open page”（`href="/components"`），claim 成立。
- **请求令牌守卫**：`requestToken` 让 `to` 变化后的迟到响应无法覆盖新文档；已有 spec
  `ignores a stale response after the target document changes` 覆盖，实测通过。
- **`to` 变化后即时重取（即便浮层已关）**：源码注释已把取舍写清（组件拿不到 popover 的
  open 状态，只能用 `hadLoaded` 当代理），`requestToken` 保证正确性，不是缺陷，不改。
- **error 态与陈旧 preview 不会同时出现**：`to` 变化时 watch 先清 `preview`；同一 `to`
  下 Retry 只在 error 态可见，`ready` 态不可达 Retry，故不存在「错误文案配旧摘要」。
- **token / a11y**：只用 `text-primary`、`--ui-primary`、`text-highlighted`、`text-muted`
  等语义 token，无硬编码颜色/圆角；触发器是 `AnnotationPopover` 的真实 `<button>` +
  `focus-visible` 轮廓，焦点管理在壳里且已有专门 spec，本形态无需重复实现。

## api-docs-field-annotation — 同族同类溢出修复；labels 重复人工判定 wont-fix

`kits/api-docs/components/FieldAnnotation.vue`（162 行）+
`kits/api-docs/composables/useFieldSource.ts`（41 行）。

### 改动：`type` span 的 `shrink-0` 把它钉在 max-content

同一类溢出，但**修法不同**，这点必须写清，否则会照抄错方案。`type` span 原本是
`shrink-0 font-mono text-xs text-muted`。长 union type 实测（375px）：

| 状态 | `scrollWidth`（`clientWidth` 恒为 288） |
|---|---|
| `string` | 288 |
| `oneof_settlement_reconciliation_batch_or_payout_adjustment_envelope` | **498** |
| 上者 + panel 级 `overflow-wrap: anywhere` | **498**（无效） |
| 上者 + span 级 `overflow-wrap: anywhere` | **498**（无效） |
| 上者 + 允许收缩（`flex-shrink: 1`） | 288 |

原因：`overflow-wrap` 只改变文本在**给定宽度内**如何断行，而 `flex-shrink: 0` 把这个
flex item 的基准宽度钉死在 max-content，宽度根本不会缩（flex item 的 `min-width: auto`
解析为 min-content，这也是兄弟元素都配 `min-w-0` 的原因）。所以「在壳
（`AnnotationPopover`）的面板上加一行 `overflow-wrap: anywhere` 一次覆盖全家族」这个
看起来最省事的修法**对本处无效** —— 这是实测出来的，不是推导。改成与 `name` / `format`
兄弟一致的 `wrap-anywhere min-w-0` 后回到 288；容器是 `flex-wrap`，短 type 行为不变，
只在空间不足时才收缩/换行。摘要 `<p>` 同步补 `wrap-anywhere`（同 DocAnnotation）；
`annotation-forms.spec.ts` 锁定 type 的收缩/断行与摘要断行类契约。

### f-fd7282669072 经人工授权标记 wont-fix

「labels 合并模式在 Term/Doc/Field 三形态各写一遍」属实：`AnnotationPopover`（2 键）、
`TermAnnotation`（2 键）、`DocAnnotation`（3 键）、`FieldAnnotation`（4 键）各有一个
`t = computed(() => ({ ...defaults, ...props.labels }))`。

复核后同意 07-29 的原判：

- 四处的键集与默认值**完全不同**，共用的只有 `{ ...defaults, ...props.labels }` 这个
  spread 语法，抽出去不消除任何逻辑重复，只消除字面重复；
- 现在每处的 `Required<Pick<Labels, …>>` 标注让缺省键在类型层被逐个约束，抽成泛型
  helper 会牺牲这份字面类型推断；
- 用户于 PR 人工复核后明确授权 `wont-fix`；本轮通过人工专属
  `--allow-wont-fix` 正式关闭，severity 由 v1 迁移产物 `unknown` 归档为 `low`。

因此本 item 现为 `verified`，后续不再因该字面重复重入每日审计。
