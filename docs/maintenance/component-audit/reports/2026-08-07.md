## api-docs-request-example — 首轮扫描并修复（change: modified, status: verified）

原 watcher 只观察数组引用，无法在 reactive 原数组增删后丢弃已移除选择；初修为同步 id-list watcher 后，又会在原地重排的中间态误清除仍有效选择。最终实现观察 id 列表并以 pre-flush 批处理：

- 同一次同步 `reverse()` / `sort()` 按最终列表判断，仍存在的 id 保持选中；
- 一次 Vue 更新结束时已不存在的 id 回退首项，之后跨更新重新加入同名项不会复活；
- component spec 分别锁定原地重排和删除后重加两条路径。
