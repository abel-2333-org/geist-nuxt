### 保留的焦点发现

在 Chromium 153、1024×900、正常 200ms 动画下，main `19a1075` 与 PR 的 children/value/anyOf 三种入口均复现：先真实 Tab 到触发器，Enter 展开并等待稳态，再 Space 收起并立即 Tab。Tab 发生在关闭动画运行中，焦点进入内容；动画后段聚焦按钮被 overflow 完全裁剪，稳定关闭后焦点落到 BODY、无 focus-visible。这不是本 PR 引入的回归，但确实影响快速键盘操作。

另外，真实 Tab 进入内容后，通过 `HTMLButtonElement.click()` 激活已有祖先触发器，同步不移动内部焦点，复现相同结果。这是程序化 DOM 激活场景，不声称界面提供 Escape 收起祖先等快捷键。报告分别保留两种输入路径及逐帧样本；动画过程中单独的 opacity 样本不混同隐藏祖先结论。

最小修复方向：关闭开始时使后代不再可 Tab，并在焦点已位于内容内时恢复到对应触发器；需验证重新打开、深链接和嵌套状态不会受影响。本轮只补证，不改组件生命周期、不扩大 PR B。该发现保持 open；#147 的七个既有 owner/findings 原样保留，不能因为对比度或此次测量执行成功而关闭。

`focus-comparison.json` 的 `verified-with-inherited-findings` 只说明两侧均执行且问题在基线已存在。新增不可见焦点、关闭完成后新增隐藏焦点和未命中动画窗口均使门禁失败。它不等于“焦点通过”，PR A 最终采纳仍需明确处理此已知问题与人工视觉确认。
