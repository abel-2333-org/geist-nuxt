## api-docs-enum-table — improved

`kits/api-docs/components/EnumTable.vue`（328 行）+ `kits/api-docs/utils/enum.ts`（56 行）。
被 `api-docs-field-item` 嵌在每一个带 enum 的字段行里，所以它的缺陷会按字段数量放大。

### 改动 1：`EnumVariant.when` 声明了却从不渲染（静默丢信息）

`utils/enum.ts` 里 `EnumVariant.when` 带着 JSDoc「When this group of values applies
(already localized)」，`references/kits/api-docs/index.md` 也把 variants 形态描述为
「取值随条件变化」——但 `EnumTable.vue` 的模板**从头到尾没有读过这个字段**。作者写了
这句话，读者永远看不到。

这不是「少一个可选特性」，是契约层已经承诺、实现层没有兑现。修法选渲染而非删字段：
删 `when` 是 public type 的破坏性收窄，且丢掉的正是 variants 形态存在的理由
（tab 标题只**命名**分组，`when` 才回答「我是不是在这一组」）。

渲染位置在 variant 选择器之下、值表之上，读序为「有哪几组 → 这一组何时适用 → 组内取值」。
经 `InlineMarkdown` 渲染，与本 kit 所有作者文案同一条通路。

**刻意用中性色而不是 amber**：`FieldItem.vue` 里那套注释（第 2 条 Condition 规则）
把 amber 家族按**填充度**分了四级——文字标签 CONDITIONAL → 带边线规则 → 填充 callout
→ Beta 徽章。EnumTable 是嵌在字段行**内部**的，这里再加一个 amber 对象会把那套分级压平。
依据：`references/foundations/focus-a11y.md`「不要只用颜色表达状态」+ FieldItem 既有的
amber 阶梯注释。

### 改动 2：筛选没有 live region

`SidebarNav.vue`（同 kit 的另一个可筛选列表）早就有 `resultsAnnouncement` /
`noResultsAnnouncement` + `sr-only role="status" aria-live="polite"`；EnumTable 的
筛选框重写整张表却是静默的，屏幕阅读器用户得不到任何反馈。

依据：Web Interface Guidelines「Async updates (toasts, validation) need
`aria-live="polite"`」+ 仓库自身先例。扁平表继续复用 SidebarNav 的契约形状
（`(count: number) => string` / `(query: string) => string`）；分组表新增
`variantResultsAnnouncement(totalCount, activeCount, activeLabel)`，在一句播报里明确
「全部选项」与「当前本地化分组」两个 scope。

默认文案取本表的领域词而非 SidebarNav 的「result」：空态本来就写作
`No matching values`，播报就是 `N values found` / `No matching values for “q”`。

### 改动 3：滚动框键盘不可达

未过滤的当前面板达到筛选阈值时，值表进 `max-h-80 overflow-y-auto` 的有界滚动区，而框内**全是静态文本**
（`<dl>` / `<dt>` / `<dd>`），没有任何可聚焦元素。结果是键盘 only 用户根本滚不到折叠线
以下的取值——这正是长枚举（≥30 项）才会触发的路径，也就是最需要滚动的场合。

依据：`references/foundations/focus-a11y.md`「键盘可达：所有可点击元素用真正的
`<button>`/`<a>` 或带 `tabindex`/`role` 的元素」；WCAG 2.1.1。

修法分成两个互不混淆的判定：**未过滤的 active group** 只负责稳定保留
`max-h-80`，避免筛选时页面突然展开；`ResizeObserver` 则按实际
`scrollHeight > clientHeight + 1` 决定滚动框是否获得 `tabindex="0"` +
`role="group"` + `aria-label` + 系统 focus 环。筛选后不再溢出就退出 tab 序列，
内容或宽度变化再次溢出就恢复。测量经 cancellable rAF 合并，卸载时取消 pending frame，
避免 ResizeObserver 同步反馈环和卸载后写状态。

### 改动 4：一次筛选，两处使用

改前 tab badge 的计数和面板实际渲染的列表**各跑一次 `filterValues`**，两者数值一致
只是巧合。改成单个 `filteredVariants` computed 同时喂 badge、body 与 live region，
一致性由数据结构保证。播报保留所有 variant 的聚合命中数，同时补当前分组命中数与
本地化 label：当前 tab 为 0、其他 tab 有结果时，不再误报全局「无匹配值」，也不会让
屏幕阅读器用户猜测当前 panel 的 scope。

顺带修掉一个边界：`variants` 缩短时选中态会滞留在已消失的 tab 上，渲染出空态而不是
回落到第一组。第一版只 clamp 索引，外部 review（codex）指出 clamp 只防「变短」——
**等长换数据集**（复用实例切换字段数据）仍会把旧索引套到无关分组。因此选中态改为持有
分组**身份**（`activeKey`：`title` → 首个取值 → 位置兜底，重名带 occurrence 后缀），
索引由 `variantKeys.indexOf` 派生：重排跟着选中项走；分组消失或换数据时 sync watch
把 key 收回首项（只 clamp 派生值而不清 key，会让旧选择在该组回来时复活）。`UTabs` 也
从 `v-model` 改为 `:model-value="String(activeIndex)"` +
`@update:model-value="selectVariant"`——高亮的 pill 与渲染的面板读同一个派生值，
不会出现「面板显示第一组、但没有任何 pill 高亮」。

依据：`vue-best-practices`「Keep source state minimal, derive everything possible
with `computed`」「Avoid recomputing expensive logic」。

### 连带改动：FieldItem 的透传键

`references/kits/api-docs/index.md` 第 285 行立了规矩：「nested chrome 本地化走同一个
`labels` 对象，不 fork 组件」。新增播报函数若不透传，双语消费方会拿到英文播报，
破坏那条约定。故 `FieldItemLabels` 加 `enumResults` / `enumNoResults` 两个透传键
及分组专用 `enumVariantResults`（纯增量，可选，无默认值——沿用「默认字符串只存在于
子组件一处」的既有做法）。

`typecheck` 当场逮到 `PassthroughLabel` 联合类型没同步，已补。这个类型正是为了防止
新透传键漏进 `t` 的默认值对象而存在的，它按设计工作了。

### 为什么没改看起来可改的地方

- **`filterValues` 每次查询为每个 variant 分配新对象数组**——文档规模（单表几十到
  上百项）下是噪音级开销。`vue-best-practices` 的性能章明确说性能优化是行为正确之后
  的独立 pass，这里没有可测量的问题。
- **`<dl>` 没有 `aria-labelledby` 指向上方的 `LABEL (N)`**——`role="group"` 已带
  `aria-label`，再挂一层会造成重复播报。

## api-docs-field-annotation — improved

`kits/api-docs/components/FieldAnnotation.vue`（162 行）+
`kits/api-docs/composables/useFieldSource.ts`（41 行）。

### 改动：未命中 ref 在 dev 下静默

组件头部注释写着「Unresolvable `field-ref` degrades to plain text（same policy as
TermAnnotation）」，但只抄了策略的一半：`TermAnnotation.vue` 在 `import.meta.dev` 下
`console.warn` 未命中的 glossary id，`FieldAnnotation` 没有。

降级对**读者**是正确的运行时行为（stale markdown 永不破页），但对**作者**必须留下诊断
——否则一个 `provideFieldSource` 里漏登记的 id，表现就是页面上少了个浮层，没人会发现。
家族两个形态共用降级策略，诊断也该共用。

依据：`references/components/overlays.md` 的 Annotation 家族契约（降级策略是家族级的）
+ 组件自身注释声明的 parity。

告警只在 `fieldRef` 存在且解析不到时触发——直传 `field` 而 `field` 为空是调用方自己的事，
不该由组件唠叨。

诊断判断抽到同 item 的 `useFieldSource.ts`，组件在 `import.meta.dev || import.meta.test`
下通过一个 `watchEffect` 自查。第一版把它抽成 `useFieldSource.ts` 的导出 helper，
外部 review（codex）指出这只是把一个只有单一调用点的组件自诊断推进了 kit 的
auto-import 公共面，且 JSDoc 声称「与单测共用」并不成立——测试从来是挂载真实
`FieldAnnotation field-ref="missing"` 断言精确 warning，而非直接调 helper。内聚回
组件后测试不变、覆盖不减：今后若组件接线被删，测试会失败，不会留下「helper 自己
通过、组件已断线」的假绿。

gallery 里 `field-ref="create-deployment.removed"` 是**有意**的降级演示，现在会打一条
dev warning；这与 `app/components/gallery/Overlays.vue` 里 `TermAnnotation
id="does-not-exist"` 的既有行为完全对称，是预期的。

复查时另补了两条 fragment round-trip：

- **FieldAnnotation 跨页链接**：组件对 raw `FieldNode.path` 编码一次；Vue Router
  解析字符串 URL 后，`app/router.options.ts` 直接以 `to.hash` 的字面值查找 DOM id。
  annotation href test + field-anchor router test 覆盖包含字面 `%` 的链接与落地滚动。
- **SiteSearch 同页焦点交接**：command palette 选择结果后，SiteSearch 同样直接使用
  `router.resolve()` 已规范化的 hash；site-search modal test 覆盖关闭浮层后的目标聚焦
  与滚动。它与 FieldAnnotation 的跨页 router 链路并行，不参与后者导航。

### 为什么没改看起来可改的地方

- **`t` computed 的 labels 合并模式在三个形态里重复**（`TermAnnotation` /
  `DocAnnotation` / `FieldAnnotation` 各写一遍 4 行 spread）。抽成共享 helper 要跨
  foundation ↔ kit 边界再加一个自动导入符号，换来省 12 行样板——收益不抵间接层，
  且 `AGENTS.md` 的 kit 依赖规则下这个 helper 只能落 foundation，让 kit 组件为了
  4 行 spread 多一条依赖边。不改。
- **`normalizePath` 是本文件私有的 5 行函数**，只有一个调用点，没有第二个消费者，
  不构成抽公共 util 的理由（`component-reflow.md` 采纳标准第 3 条「至少有明确的复用场景」）。
- **`useFieldSource` 注入的是普通对象而非 reactive**——与 foundation 的 `useGlossary`
  完全同构，是家族一致的刻意选择（页面级静态数据）。单方面改会让两个孪生 composable 漂移。
- **未动 props / emits / slots 公开契约**：`dependedBy` 为空，但已 copy-in 的消费项目
  不可见，破坏性变更的收益这里不存在。

## foundation-inline-code — clean

`foundation/components/InlineCode.vue`（18 行）。被 5 个 item 依赖
（`foundation-inline-markdown`、`api-docs-enum-table`、`api-docs-field-item`、
`api-docs-field-annotation`、`api-docs-webhook-protocol`），是这簇里最底层的原子。

**逐条过了四个维度，没有可做的改动：**

- **晋升**：已在 foundation 根，位置正确（跨场景裸名原子，符合 `component-reflow.md`
  第 3 节「跨场景裸名组件可放 `foundation/components/` 根」）。
- **精简**：18 行、单一职责、零 props。它把 `ProseCode` 的两处主题默认拉回 Geist
  基线——圆角回控件档（`rounded-sm`，6px）、字号回 Copy 13 Mono（`text-code`，
  对应 `foundation/assets/css/main.css` 的 `--text-code: 0.8125rem`）。两处偏离都
  在源码里写明了原因，没有无据硬编码。
- **优化**：非交互元素，无 focus / aria / 键盘面。明暗主题由 `ProseCode` 的语义
  token 承担。换行策略**刻意不内建**：调用方按上下文传 `break-all`（EnumTable 的值列，
  窄列要断得狠）或 `wrap-anywhere`（FieldAnnotation 的浮层，宽度自由），单根节点
  attrs fallthrough 自动合并 class。这比在组件里塞一个 `wrap` prop 更对——
  `vue-best-practices`「Fallthrough attributes: wrapper/base components must
  forward attrs/events safely」。
- **重构**：无 script 逻辑可写坏；命名符合 `component-reflow.md` 三原则（`InlineCode`
  是成熟 UI 模式词，描述形态而非内容）。

**没有为了产出而制造 churn。** 唯一一处犹豫是空的 `<script setup lang="ts">` 块
（只装注释），但它承载的是两处主题偏离的**决策记录**，删掉会丢掉「为什么不用
`ProseCode` 默认值」这个信息，得不偿失。
