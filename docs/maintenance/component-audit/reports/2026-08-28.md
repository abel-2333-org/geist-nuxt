### 为什么没改某些看起来可改的

- **`#${encodeURIComponent(path)}` 三处出现**(useFieldAnchor、RelationSourcePath、FieldAnnotation,
  后者簇外,由反向横扫命中):这是被 reference 钉死为公开契约(「进入 URL hash 时只编码一次」)、
  三处各有测试断言的**编码约定**,不是漂移中的重复实现;抽 `hashFor` helper 需改动 field-item
  切片(useFieldAnchor 属其分发闭包),触发 co-review 且三处用途不同构(裸 fragment / 完整 URL /
  page 前缀),一行表达式的抽象收益不抵成本。不记 finding。
- **`useFieldAnchor` 的引入方式不一致**:SchemaComposition 走 kit auto-import,RelationSourcePath
  显式相对路径 import。两种在源与 copy-in 目标布局下均正确解析,显式 import 亦更利于 SFC 类型
  导出场景的自包含;纯风格差异,无行为风险,不制造 churn。
- **`segments: []` 退化输入**:此时最后一段即 scope label,linked 态无 underline 提示。按契约
  「主层级必须包含完整 hierarchy」,空 segments 属 consumer 契约违规输入,组件不做防御性校验
  (与 kit 一贯的「显示模型已解析、不二次校验」边界一致),不记 finding。
