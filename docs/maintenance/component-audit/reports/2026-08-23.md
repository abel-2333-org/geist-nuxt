### 2. 全局 `/` 快捷键:手写 listener vs Nuxt UI `defineShortcuts`(精简 / 重构维度)

08-21 横扫记到「typing-guard 全仓仅 SidebarNav 一处,SiteSearch 走内建 shortcut」但未评估替换。今天读 `@nuxt/ui/dist/runtime/composables/defineShortcuts.js` 逐条对比:

| 能力 | SidebarNav 手写 `onKeydown` | `defineShortcuts` |
|---|---|---|
| 修饰键过滤(meta/ctrl/alt) | 显式排除 | 精确匹配(等价) |
| 输入态守卫 | `INPUT / TEXTAREA / SELECT / isContentEditable` | `usingInput`:`INPUT / TEXTAREA / contentEditable`,**不含 SELECT** |
| 按键可配置(`searchShortcut` prop) | 直接比较 `e.key` | `toValue(config)` 支持 computed,可行 |
| `searchable=false` 关闭 | 早返回 | config 置空对象,可行 |
| SSR | `onMounted` 注册 | vueuse `useEventListener`,等价 |

**判定:不改,不记 finding。** 替换能省约 8 行并对齐 nuxt-ui 约定,但会丢掉原生 `<select>` 聚焦时的守卫——消费项目的 docs shell 可能用原生 select,届时按 `/` 会抢焦,属行为契约收窄(reference L118「正在输入时不抢焦」),收益低于风险。组件注释已说明守卫意图,维持现状。

**Universal-claim 核证**:reference L118 称「`/` 聚焦搜索(正在输入 / IME 组字时不抢焦)」。代码未直接检查 `isComposing`,但 IME 组字必然发生在 INPUT / TEXTAREA / contentEditable 目标内,`typing` 守卫传递性覆盖,claim 成立,不需收窄。
