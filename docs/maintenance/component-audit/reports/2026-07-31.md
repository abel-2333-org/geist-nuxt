## foundation-annotation-popover(clean)

Annotation 家族的交互壳。源码逐条核对 `references/components/overlays.md` 的实现契约;`tests/component/annotation-popover.spec.ts`(381 行)覆盖核心 click/hover、焦点、disabled 与 loading/error journey,静态 a11y、token 和响应式类由源码核对:

- **click 骨架 + hover 增强**:`UPopover mode="click"` 受控;`pointerType === 'mouse'` 才走 150ms/250ms 定时器;touch/键盘/click 三端一致(overlays.md「行为边界」条款,规避 HoverCard 触摸不可达问题)。
- **OpenSource 焦点策略**:keyboard 打开聚焦面板首个动作(无动作聚焦面板本体 `tabindex="-1"`);pointer/hover 打开 focus-neutral;关闭仅在焦点确属面板(或 keyboard 会话)且 nextTick 确认焦点丢失后归还触发器;hover 开启且触发器持焦时 forward Tab 引导入面板并移交 keyboard 所有权。focused suite 覆盖 keyboard entry、hover focus-neutral、Shift+Tab、外部点击和 mouse 掠过等主要 journey。
- **a11y / token 合规**(web-design-guidelines + geist-nuxt 硬规则):真实 `<button>` 触发器、`focus-visible:outline-*`、`touch-manipulation`、装饰图标 `aria-hidden`、loading `aria-busy` + sr-only `role="status"`、error `aria-live="polite"`、文案 `Loading preview…` 用 `…`;全程语义 token(`bg-elevated`/`outline-primary`/`text-dimmed`),无硬编码颜色;面板 `w-72 max-w-[calc(100vw-2rem)] sm:w-80` 响应式;`transition-colors` 不用 `transition: all`。
- **精简维度**:昨日 api-docs-field-annotation 的 wont-fix finding(f-fd7282669072)建议「与 popover 簇一起复审 labels 合并模式」。本轮复审结论:三形态各 4 行 spread 的 `t` computed 维持现状 —— 抽共享 helper 必须落 foundation 并给 kit 组件新增依赖边、跨 copy-in 拓扑边界增加自动导入符号,收益不抵间接层。**确认原 wont-fix 判定,不再翻案。**
- `AnnotationPopoverLabels` 落 `utils/annotation` 供跨拓扑裸引用、SFC 顶部 type-only re-export 兼容旧 copy-in 消费者:与 registry `files[]` 一致,契约有明文依据。

## foundation-semantic-badge(deferred,open finding)

组件本体的 tone→color 映射、业务隔离和 gallery 六态达标:`BADGE_TONE_COLOR` 以 `Record<BadgeTone, …>` 强制 tone 穷尽;域值→tone 映射留在 kit preset;gallery 覆盖全部 6 个 tone。

**Finding(low,open)**:`references/components/data-display.md` 将 `icon` 标为可选,却同时要求 SemanticBadge「务必配 icon + 文本」;组件 props 允许省略 `icon`,`HttpMethodBadge` / `WebhookBadge` 也合法地只传 label,且 `label: string` 可为空。当前 API/消费者与公开 universal claim 不一致,不能以「label 必填」判定语义一定不只靠颜色。契约应收窄为非空文本必需、icon 可选,或在 API 层强制现有声明。

**为什么本轮没有直接修**:`data-display.md` 同时属于 `foundation-inline-markdown` 的 verified scope,单独收窄文案会让其 evidence stale;inline-markdown 不在本轮计划,不能经官方 `--record` 流程同步刷新。故本轮记 deferred,待两项同批时修复权威 reference 并重录 evidence。

**为什么不补专属测试**:无分支逻辑、无交互、无状态;穷尽性靠类型系统,视觉靠 gallery。`component-reflow.md`「只保留有意义的状态,不为纯展示件制造虚假矩阵」——补展示快照测试属无谓 churn;本次 finding 是公开契约冲突,不是渲染回归。

**为什么不动 `import ... from '../utils/badge'`**:相对引用在源仓库(`foundation/components` → `foundation/utils`)与 copy-in 后(`app/components` → `app/utils`)保持同构,两侧均成立;换裸自动导入无行为收益。
