### api-docs-sidebar-nav — modified(status: deferred,1 条新 medium finding)

**修复(本轮落地)**:搜索框 `@keydown.esc` 原直接绑 `clear`,无 `isComposing` 守卫——WebKit 在 IME 组字中按 `Esc` 取消候选词时,keydown 带 `key='Escape'` 且 `isComposing: true`,会把整个查询连同焦点一起清掉。对以 CJK 场景名(「批处理」「订阅」)为一等检索输入的组件,这是真实缺陷(违反 Web Interface Guidelines 键盘/表单条款「不得干扰输入法组字」;reference 自身也承诺「IME 组字时不抢焦」)。修法:`onSearchEsc` 守卫 `e.isComposing` 后再 `clear()`,`sidebar-nav.md` a11y 节同步补充契约措辞。

**测试补齐**:SidebarNav 本体此前无 spec(仅内部 `SidebarScenarioTags` 有),文档化行为契约全靠人工核对。新增 `tests/component/sidebar-nav.spec.ts`(10 tests)锁定:搜索三轴匹配(label / method / scenario)与 `命中/总数` 计数、板块标题命中保留整块、polite live-region 播报与空态、`searchAriaLabel` 剥结尾省略号、Esc 清空 + IME 组字例外、active 单源规则(显式 boolean 优先 / 含 `#` 不自推断 / 纯路径按解析后 route 推断,兼验 `sections` 扁平入参包装)、全 CJK 板块 label 的 slug 回退不共键、调宽手柄键盘操作(←/→ 步进、Home/End clamp、双击复位)与 `resizable=false` 不渲染手柄。

**新 finding `f-12d73e8bc49d`(medium,open)**:反向横扫命中簇外 foundation——SidebarNav 内联的 width resize(拖拽数学、`clampWidth`、键盘步进、双击复位、持久化)与 `useSplitPane` + `SplitPaneHandle` 能力重复,且行为不一致:

1. 持久化用 `localStorage` 且在 `onMounted` 后读取——lg+ 桌面端持久宽度 ≠ `defaultWidth` 时,每次刷新先渲染 288px 再跳到持久宽度;`useSplitPane` 用 cookie 种子 `useState`(`useCodeWrap` 同款约定),SSR 首帧即正确、无跳变;
2. 内联版缺少 `useSplitPane` 已有的 `Esc` 取消拖拽回滚。

组件注释解释了不用 Nuxt UI `UDashboardResizeHandle` 的原因,但未对齐本仓库自己的 foundation 方案。收敛属破坏性:`widthStorageKey` prop 公开语义即 localStorage(reference 与 gallery 文案均明言)、消费端已存宽度需迁移、registry 拓扑需新增 `foundation-use-split-pane` 依赖,故记 deferred 交人工决策。

**为什么没直接修**:同 PR 无法改完所有调用点(下游 copy-in 消费端的已存 localStorage 宽度无迁移路径),且视觉锚点(1px rule 手柄 vs SplitPaneHandle grip pill)需人工定夺是否统一。

**为什么没改看起来可改的**:`isItemActive` 每行渲染被调 3 次(`:active` / `aria-current` / `:class`),每次 `router.resolve`——导航量级(<100 行)下成本可忽略,memoize 增加间接层无实测收益;`:key="item.to ?? item.label"` 理论上可撞键,但同 `to` 重复项本身是数据错误,不加防御。
