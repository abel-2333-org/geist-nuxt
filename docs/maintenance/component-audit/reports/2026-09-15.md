**观察(非 finding,交人工决策)——嵌套行 hover 时 gutter 链接图标压在树形引导线上。**

- **复现**:任意带 `children` 的 FieldItem,视口 ≥ `lg`(1024px)且 `pointer: fine`,展开子字段后 hover 任一子行。已部署 gallery(`/kits/api-docs` 「字段树」`gitSource` → `repoId`)在 1280×900 浅色下用 JS 实测:子行 gutter 按钮 `getBoundingClientRect()` 为 x 25–43px,子字段容器 `border-s`(1px)位于 x 32px,即引导线穿过 14px 图标中部;顶层行按钮 x 8–26px,无引导线,不受影响。
- **成因**:gutter 按钮固定 `-start-6`(24px)偏移,子字段容器缩进 `ps-3 @sm/field:ps-4`(12 / 16px),24 > 16 故按钮必然跨过引导线;这是几何结构性重叠,不是回归——08-29 把 gutter 改为 `lg:pointer-fine:flex` 时该几何关系即已存在。
- **为什么不记 finding**:hover-only、桌面精细指针专属、不影响可访问性与操作(按钮 hit area 完整、focus 环正常);`references/foundations/` 与 `component-reflow.md` §2 只要求 hover / focus-visible 状态被验证,没有可引用的「不得与引导线重叠」条款;frontend-design 的「细节精致」是指导而非条款。按 SKILL.md §5「说不出依据的改动不要做」与 §7 标准,记观察而非 finding。
- **修法与权衡(留人工)**:(a)给 gutter 按钮加不透明底色(`bg-default`)让引导线在图标处断开——最小改动,但把「字段树落在 `bg-default` 表面上」写死进分发组件,消费项目把字段树放在 `bg-elevated` 卡片内时 hover 会出现一块错色方块;(b)把子行的 gutter 偏移收成不跨线——18px 按钮要完全避开 16px 处的线,要么起点 ≥ -15px(与行文字重叠)要么终点 ≤ -17px(`-start-9`,落进父行文字列),两者都比现状差;(c)保持现状,接受图标「挂在」分支线上的读法。倾向 (c) 或 (a) 之间由人工按消费项目的实际表面决定;若选 (a),需同时在 reference 记录表面假设。
