## api-docs-site-search — 记 1 个 low finding(change: none, status: deferred)

核证通过的部分:

- **异步契约**:debounce(`searchDelay` + setTimeout)、stale response cleanup(`active` 旗标 + `onCleanup`)、失败态 `searchFailed` 与「失败且无可用结果时才区分三态」的文档化行为逐条对应 index.md「SiteSearch 契约」;`ignoreFilter: true` + `preserve-group-order` 兑现「数据源排序不再被 Fuse 重排」。
- **hash 焦点交接**:`router.resolve` 单次解码、opaque id 原样使用、`prefers-reduced-motion` 分支——site-search.spec.ts 的 `res_state%25` 用例覆盖。
- **a11y 已达标面**:trigger 是 icon+文案按钮,窄屏降为 icon-only 时 `aria-label` 兜底;UKbd 装饰 `aria-hidden`;`#content` 覆盖场景下 UModal 渲染 VisuallyHidden DialogTitle(读 @nuxt/ui Modal.vue 源码核证),`modalTitle` 仍是对话框可访问名。
- **fuse 配置**:`useTokenSearch` 在本仓库 fuse.js 版本是真实选项(查 node_modules 类型定义证实,非 dead config);自定义 `fuse` 经 defu 与默认值合并,`matchAllWhenSearchEmpty: true` 保留,空查询仍展示静态导航组。

**Finding(low, open)**:面板的 searching/失败/零结果状态只渲染在 UCommandPalette `#empty` 槽的普通 div 里,整条链路(@nuxt/ui CommandPalette、reka-ui Listbox/Combobox)无任何 live region,SR 用户输入无匹配 query 或异步失败时听不到任何反馈——涉 WCAG 4.1.3 Status Messages,且与 kit 内 SidebarNav/EnumTable 的 sr-only `role="status"` 播报契约不一致。

**为什么本轮不修**:可靠的播报需要持久 live region + 「过滤结果为空」这一状态,而 UCommandPalette 不暴露过滤计数(读源码证实无相关 emit/slot 数据);本地半修只有两条路——仅播报 searching/failed(与文档化的「静态有命中时失败静默」视觉契约漂移,且逐键 toggle 会制造 SR 噪音),或用 `#empty` 槽挂载信号镜像状态(依赖上游渲染时机,announce-on-mount 在 NVDA 上不可靠)。两条都跨 Nuxt UI 契约边界或制造新的不一致,按「修复量大且跨契约边界走 deferred」交人工决策:接受 combobox 模式静默(与主流命令面板一致)、上游 feature request、或采用挂载信号方案。
