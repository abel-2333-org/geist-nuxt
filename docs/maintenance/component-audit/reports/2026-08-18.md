## foundation-inline-code(modified → verified)

**问题**:仓库对「代码内容不被机器翻译」已有一致立场 —— `CodeBlock.vue:258` 注释明确 "code is identifiers" 并在 `<pre>` 上设 `translate="no"`,`OperationTarget.vue:233/252` 的 `<code>` 同样;`InlineMarkdown.vue:45` 与 `FactRow.vue:43` 则各自给 `InlineCode` **外置补丁**式地传 `translate="no"`。但 `InlineCode` 原子自身不设,导致直连消费点(`EnumTable.vue:291` 的枚举值、`FieldItem.vue:282/461` 的默认值与示例、gallery 示例)渲染的字面值仍会被浏览器机器翻译改写。同类内容(字面标识符/值)在不同路径下行为不一致;消费者反复在外部补齐同一行为,正是该行为本该属于原子契约的信号。

**修法**(本次落地):

1. `foundation/components/InlineCode.vue`:模板内建 `translate="no"`,注释记录依据与覆盖通道。Vue 3 fallthrough 合并中父级 attr 在后、覆盖模板静态 attr(`class`/`style` 除外),消费者仍可对单个实例传 `translate` 覆盖 —— 已由测试实证。
2. `foundation/components/InlineMarkdown.vue`:删除冗余的 `{ translate: 'no' }` 外置传参,收敛到唯一实现;`inline-markdown.spec.ts:31` 既有断言(code token 渲染 `translate="no"`)继续守住该路径。
3. `references/components/data-display.md`:InlineCode 段补契约描述(默认 `translate="no"`、与 CodeBlock 同因、可 fallthrough 覆盖)。
4. 新增 `tests/component/inline-code.spec.ts`:锁定默认 `translate="no"`、fallthrough 覆盖(`translate="yes"` 生效)、Geist 校准类(`rounded-sm` / `text-code`)三条契约。
5. `scope-v1` 显式绑定 `@nuxt/ui`(`ProseCode` 根节点/attrs 转发/主题行为)与 `vue`(fallthrough attr 合并顺序),使上游内容版本变化时该 owner 正确 stale。

**为什么没改 FactRow**:`kits/api-docs/internal/FactRow.vue:43` 的显式 `translate="no"` 在原子内建后成为无害冗余(同值重复声明)。删它只省一行,却会把 `api-docs-webhook-protocol`(14 文件 scope)拉入 required co-review,成本收益不成比例;留待该 item 下次按计划轮到时顺手收敛。
