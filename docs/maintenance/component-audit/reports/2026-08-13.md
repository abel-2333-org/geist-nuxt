## 外部依赖证据契约

- result 只声明依赖 `name` 与结论成立的 `reason`，版本必须由 recorder 从精确 evidence head 的已提交 `pnpm-lock.yaml` Git blob 推导，人工不能手填。
- lockfile 必须是 v9；直接依赖从根 importer 解析，传递依赖必须只有一个内容 resolution。精确 semver 与可选 `patch_hash` 共同构成内容标识，peer context 不纳入证据；缺失、多版本、范围值、异常结构、symlink 或不可读文件一律 fail closed。
- `audit:verify` 读取当前普通 lockfile，而不是历史 `HEAD` blob，所以待提交的依赖升级也会立即令绑定 owner stale。
- owner 推导比较 base 与 HEAD 的已提交依赖内容标识；dependency-only diff 只要求真正绑定该依赖的条目 co-review。删除既有 binding 也必须伴随显式结果与真实 owner 变化，不能静默逃逸。

这套约束把“上游行为前提”提升为一等证据，同时保持对单人 + AI 协作友好：AI 只说明依赖与原因，脚本负责取版本、算影响面、阻断漏审。
