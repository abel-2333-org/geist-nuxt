## api-docs-method-badge — 新记 1 项 open finding（change: none, status: deferred）

### 新 open finding：空白 method 会移除文本主信号（severity: low）

`HttpMethodBadge.method` 接受任意 `string`；空串或纯空白经 `toUpperCase()` 后仍为空，查表必然走 neutral fallback，最终 `SemanticBadge` 的 `label` 也为空。此时 neutral fallback 的视觉样式会成为唯一可见信号，与「方法文字是主信号、颜色仅作强化」的公开契约不一致。

未知但非空的 token（例如当前 sidebar 过渡约定中的 `EVENT`）仍会保留原文并走 neutral fallback，未发现同类问题。

**为什么本批不改运行时**：`HttpMethodBadge.vue` 与其契约引用同时属于 `foundation-semantic-badge` 等既有共享 evidence scope。复审中曾验证直接修复会让三个共享 owner 的 digest stale；本批不扩大为跨 owner 重录，因此撤回该运行时改动，将原来的错误 `verified` 改为 `deferred/open`。后续应在共享 owner 同批处理中决定「拒绝空白输入」或「渲染明确 fallback」，并补 focused spec。

本次 scope 覆盖组件的 gallery、直接消费面、preset、`SemanticBadge` 下游渲染与公开语义契约，完整证明“输入 → fallback → 空 label → 违反文本主信号契约”的链路。finding id：`f-d4a766b14726`。

## api-docs-sidebar-nav — 修复 2 项 + 新记 1 项 open finding（change: modified, status: deferred）

### 已修复 1：自然宽度测量与可见渲染口径不一致

原实现用标签自然宽度做 fit 计算，但已测量的可见标签仍带 `max-w-28`，会让「被算法判定放得下」的长标签在 UI 中被截断，而且因没有 overflow trigger 而无法揭示全文。

修复后 `max-w-28` 只用于 SSR / 首帧未测量状态；完成测量后，fit 数学与可见渲染都使用自然宽度。focused spec 覆盖完整平铺、折入 `+N` popover、一个也放不下时退化为 count chip。

### 已修复 2：`+N` 预留宽度错误复用总数

原实现只测量 `+scenarios.length`，但候选 fit 的真实 trigger 是 `+(total - k)`。当隐藏数量跨越 9→10、99→100 等位数边界时，错误预留会少展示本来能放下的标签。

修复后隐藏测量层按数字位数渲染 `+1`、`+10`、`+100` 等样本；`tabular-nums` 保证同位数数字等宽，样本数仅为 `O(log10 n)`。fit 循环按每个候选的真实 hidden count 取对应宽度。新增边界 spec 证明：150px 预算下应保留 9 个标签并显示 `+1`，而不是因复用 `+10` 宽度多折叠一个标签。

### 新 open finding：eyebrow 字号游离于 typography 字阶（severity: low）

`SidebarNav.vue` 分组 eyebrow 使用 `text-[0.6875rem]`（11px）与 `tracking-[0.14em]`，没有落入 `references/foundations/typography.md` 已定义的最小 Label 12（`text-xs`）字阶。

两个方向都合理：归一为 Label 12，或在 typography contract 正式增设 11px eyebrow 档。该选择会改变视觉层级 / foundation 契约，继续交人工决策；finding 只描述当前组件内的契约偏差，不再声称它是全部分发源码中的唯一任意字号。finding id：`f-b401a2e3fcdb`。

本次 scope 补齐 `AGENTS.md` 与 typography authority，并保留 app demo、组件、internal helper、references、focused spec，避免 universal claim 超出 evidence 边界。
