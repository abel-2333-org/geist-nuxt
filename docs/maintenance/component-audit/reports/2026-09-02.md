### foundation-annotation-popover(AnnotationPopover + utils/annotation)

- **晋升**:无。壳与 `AnnotationPopoverLabels`(utils/annotation)的拆分正是跨 copy-in 拓扑边界的既定设计(裸引用可达),三个形态(Term/Doc/Field)已覆盖复用场景。
- **精简**:278 行全部服务单一职责(行内注释交互壳)。焦点管理(OpenSource 记录 + onOpen/CloseAutoFocus 接管)与 hover 定时器高度耦合于本组件语义,抽 composable 只会增加间接层——全仓横扫确认 pointerenter/leave 定时器模式仅此一处,无第二消费者。
- **优化**:逐条对照 overlays.md 契约核证——click 骨架 + mouse-only hover(`pointerType === 'mouse'` 守卫);keyboard 打开进面板首个动作、hover/pointer 打开 focus-neutral;关闭仅在 nextTick 验证「焦点确实丢失」后归还 trigger;forward-Tab 从持焦 trigger 引导进面板并切换所有权;disabled 中途翻转清定时器并关面板;loading(`aria-busy` + sr-only status)/ error(live region + retry)chrome 完整。`touch-manipulation`、`focus-visible` 环、`w-72 max-w-[calc(100vw-2rem)]` 视口约束均在位。
- **重构**:无。props/emits/slots 契约与 reference 一致;381 行 focused spec(annotation-popover.spec.ts)覆盖上述全部行为路径。
- **Universal claims 核证**:源码注释「a real outside-click target never gets its focus yanked to the trigger」由 outside-click 不夺焦测试锚定;「merely crossing the trigger with a mouse must not reclassify it as hover」由 click 会话 hover 扫过测试锚定;无已知反例。
- **为何没改 `scheduleClose` 不清既有 closeTimer 就覆盖**:推演了全部指针路径(trigger↔panel↔outside),任何能产生第二次 schedule 的路径必先经过 `cancelClose`/`clearTimers`/定时器触发,孤儿定时器不可达;为不可达路径加防御属无谓 churn。

### foundation-doc-annotation(DocAnnotation)

- **晋升**:无。管线无关(`load` 函数 prop)是刻意设计,@nuxt/content 适配留给消费方薄 adapter,契约在 overlays.md 有明文论证。
- **精简**:138 行,状态机(`idle/loading/ready/error`)+ requestToken + `to` watch 各司其职。requestToken 与 `useFieldAnchor` 的 navigationToken 同为 token 失效概念但形状不同(fetch 结果守卫 vs 多步导航中止),仅两处且无行为分歧,抽取属投机性抽象,不记 finding。
- **优化**:error 态不死路(「打开页面」动作常驻)、`wrap-anywhere` + `line-clamp-4` 防长 token 溢出、关闭后再导航防止浮层跨页存活,均有测试或注释契约锚定;trigger 强调色走 `--ui-primary` token。
- **重构**:无。`to` 变化时 drop 缓存 + 已加载则立即重取(开着的面板绝不显示上一文档),watch 只 key `to` 不 key `load`(inline closure 身份不稳)的取舍有注释论证且与测试一致。
- **Universal claims 核证**:「a late response can never overwrite the newer document's preview」由 stale-response 测试(双 promise 乱序 resolve)锚定;「The error state never dead-ends」由 error 态保留导航链接测试锚定;无已知反例。
