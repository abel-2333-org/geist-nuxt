### api-docs-sidebar-nav(SidebarNav + SidebarScenarioTags)

- **晋升**:无。ADR-005 裁定 SidebarNav 留在 API Docs kit(数据模型含 method / scenario / endpoint 领域概念),本轮复核仍成立;`SidebarScenarioTags` 是 internal helper,随 item 复制、不公开自动导入,粒度合理。
- **精简**:无。632 + 259 行各司其职(导航树 + 过滤 + 调宽 / 测量式溢出);registry `files[]` 两条与相对 import 一致,`registryDependencies` 五条逐一有真实消费(`geist-foundation`、`HttpMethodBadge`、`useSplitPane`、`useRafTask`、`SplitPaneHandle`),无冗余闭包。
- **优化 / 修复(本轮落地)**:**active 派生在模板内重复求值,且落在拖拽热路径上**。原实现每行三处调用 `isItemActive(item)`(ULink `:active`、文字色 `:class`、`aria-current`),每次都走 `router.resolve()`;而组件根节点的 `:style="{ '--api-docs-nav-w': width }"` 与 `SplitPaneHandle :value="width"` 都读 `width`,拖拽手柄的每一 rAF 帧、搜索框的每次键入、任何板块开合都会让整个 render 函数重跑。**复现输入**:50 个 endpoint 项的导航,聚焦手柄按一次 `ArrowRight`,spy `router.resolve` 计数 = **150**;拖拽时该数字按帧重复。**修法**:`resolveSection` 把每行映射为 `{ item, active, scenarios }`,`isItemActive` 只在 `resolved` computed 内每项调用一次;模板改读 `active` / `scenarios` 字段。修后同一输入计数 = **0**(computed 缓存;只有 route / query / groups 变化才重算)。severity **low**(仅影响大导航 + 拖拽/键入时的主线程占用,无功能缺陷),影响范围仅 SidebarNav 自身渲染。**依据**:vue-best-practices `reactivity.md`「keep source state minimal, derive with computed; avoid recomputing expensive logic in templates」;审计协议 §5「性能:computed/watch 滥用」。API shape 与行为契约均未变:`sidebar-nav.spec.ts` 的 active 单源用例(显式 boolean / `#` 不自推断 / 解析路径匹配)、搜索、IME、resize 全部原样通过。
- **reference 修正(本轮落地)**:`sidebar-nav.md` props 表 `searchPlaceholder` 写「默认 `Search`」,代码默认是 `Search…`(aria-label 才剥掉省略号)。08-22 / 08-23 / 08-24 三份报告都标为 nit「可在人工评审时顺手修」但一直未修;今日纳入本 PR,表格改为「默认 `Search…`;同时派生搜索框 aria-label(剥掉结尾省略号,即 `Search`)」。依据:reference 是分发契约真源,默认值属公开事实。
- **重构**:无。props / emits / slots 契约与 reference 一致;命名(`groups` / `sections` / `kind` / `scenarios`)符合 `component-reflow.md` 三原则。
- **复核无回归的既有契约**:搜索三轴过滤(label / method / scenario)+ 板块标题命中整块保留 + `命中/总数` 计数;UCollapsible 全受控 + 按 group 命名空间的开合 key + 搜索期临时 map;`/` 全局快捷键 typing-guard 与 `isComposing` Esc 守卫;stretched-link 行(ULink 覆盖层 + `pointer-events-none` 兄弟内容层,仅 `+N` 触发器 `pointer-events-auto`)避免 `<button>` 嵌 `<a>`;`SidebarScenarioTags` 隐藏测量层不设 `max-w-28`、按隐藏数位数预留 `+N` 宽度、`fonts.ready` 后重测、`useRafTask` 合帧;`SplitPaneHandle appearance="edge"` + `useSplitPane` cookie 种子 SSR 稳定、16/48px 步进、Home/End/Enter/双击、Escape 回滚;`aria-controls` 指向 SSR-stable nav id。DocsShell 的抽屉实例(`USlideover #body`,仅打开时挂载)与桌面实例(`v-if="isDesktop"`)互斥,两个 `window` `/` 监听不会同时存在。
- **Universal claims 核证**:「links containing `#` never self-infer」——`isItemActive` 对 `includes('#')` 直接返回 false,spec 锁定;「opening the scenario list never also navigates the row」——触发器是 ULink 的兄弟而非子孙,事件不会冒泡到 `<a>`,结构性成立;「a tag always renders WHOLE(post-measure)」——测量后无 `max-w-28`、贪心已证明可放下,`sidebar-scenario-tags.spec` 用例 1 锁定;「recomputing visibility never feeds back into the measured width」——测量对象是 `flex-1` 根节点的 `clientWidth`,由父行剩余空间决定,与可见 tag 数无关,成立。
- **为什么没改看起来可改的**:
  - `:key="item.to ?? item.label"` 在同板块两项同 `to` 时会重复——需要 `to` 相同且并列的两个 endpoint 项,属数据错误而非组件边界,且引入 index 后备会破坏搜索过滤时的 DOM 复用,不动。
  - `HttpMethodBadge size="sm"` 显式传默认值——与 LifecycleBadge 并存时的对齐约定由 08-01 裁定为显式记录,不动。
  - 搜索 `matchesText` 对 `method` 用原始字符串而非归一化 token——查询已 `toLowerCase`,`' get '` 也能被 `get` 命中,无功能差异,不为对称性加代码。
  - `/` 快捷键改用 `defineShortcuts`——08-23 已比较过:内建 shortcut 不识别 `isContentEditable` 且 `usingInput` 语义不同,手写 guard 保留。

### api-docs-method-badge(HttpMethodBadge + method-preset)

- **晋升 / 精简 / 重构**:无。40 + 40 行的 preset 包装层,`HttpMethodBadge` → `SemanticBadge` 原子 → `BADGE_TONE_COLOR` 三层各守一职;`index.md`「HttpMethodBadge / WebhookBadge 是平行原子,不合并成 `OperationBadge kind=…`」裁定复核仍成立(HTTP 动词封闭集 vs 事件标识开放集)。

- **消费面复核**:SidebarNav 定宽槽 `w-14`、SiteSearch `#item-leading`、OperationHeader `kind="endpoint"` 分派、gallery 四页 + DocsShellReference——全部只传 `method`(+ 可选 `size`),无绕过 preset 直接拼 UBadge 的调用。
- **为什么没改看起来可改的**:`HttpMethod` 联合不含 `HEAD` / `OPTIONS`——它们走 neutral fallback 且保留 token 文本,reference 明言「未知非空 token 保留规范化文本并走 neutral fallback」,扩词表属产品决策;`size` 默认与 SemanticBadge 重复——08-01 已裁定为对齐约定的显式记录。
